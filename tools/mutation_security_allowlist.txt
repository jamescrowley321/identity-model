# Equivalent-mutant allowlist for `make mutation-security` (Epic 19 G.1).
#
# mutmut occasionally emits an *equivalent* mutant: a syntactic change that is
# semantically identical to the original and therefore impossible to kill with
# any test. Waive one with a line of the form
#
#     <exact mutant name> <16-hex diff hash>   # justification
#
# where <hash> is `python tools/mutation_security.py --hash <name>` (a hash of
# the mutant's `mutmut show` diff *content* — the transformation, not its index).
#
# WHY the hash (issue #615): mutmut numbers a function's mutants densely
# (`{name}_{i+1}`), so that `_N` index is NOT stable — adding/removing a construct,
# or the changed-line pre-filter compacting the generated list, renumbers every
# downstream mutant. A name-only (index-keyed) waiver then silently rebinds to a
# DIFFERENT mutant; in a security gate that is a fail-open (a real, killable
# survivor inherits a stale waiver and the gate passes green). The gate therefore
# waives a survivor only when BOTH its function AND its current diff hash match an
# entry here, so renumbering can neither rebind a waiver nor lose the genuine
# equivalent. A name with no hash is a hard error, never a silent pass.
#
# Every entry weakens the gate, so keep the justification concrete and specific.
# The `_N` index in the name is only a human label — the (function, hash) pair is
# the actual key — but keep it pointing at the mutant the hash was taken from.

# R.9 issuer pinning (_enforce_allowed_issuers): the `else` branch sets
# `candidates = []`; this mutant sets it to `None`. Both fall straight into
# `if not candidates:` — `not []` and `not None` are both True — so both raise
# the identical "no issuer was resolved" InvalidIssuerException and the for-loop
# below is never reached. No input that reaches the else branch can observe []
# vs None: semantically equivalent, unkillable.
